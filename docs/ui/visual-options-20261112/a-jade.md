# A 方案：青绿行军

本方案是《军师请下令》黄巾关的浏览器可点击界面提案，评估布局、字级、状态与材质。地图、武将全身像和头像沿用正式工程素材；本轮没有完成地图或人物重绘，也没有进行 Unity 画面、APK 或真机验证。

## 视觉方向

青玉令牌作为唯一强识别元素，浅绢与暖铜约束操作边界，地图保持明亮。将操作收在顶部与底部，避免面板切碎战场；铜色只出现在边线、军饷图标与少量角标。底部将牌采用浅浮雕边界、统一头像足线和窄幅状态签，强调“三国行军”的材质关联。

| 色彩 | HEX | 用途 |
| --- | --- | --- |
| 墨青 | `#183E37` | 正文、主要数字、焦点轮廓 |
| 青玉 | `#3A7861` | 军令主按钮、选中、已上阵状态 |
| 竹叶 | `#8BA779` | 选中晕边、范围辅助底色 |
| 浅绢 | `#F4F0DD` | 顶部、底部、提示条的操作承载面 |
| 暖铜 | `#B28B52` | 细线、军饷图标、次级结构 |
| 玉雾 | `#E0EBDE` | 将牌与成长检查器的浅底 |

透明度用于同色分层，不给地图整体套滤镜，不依赖发光建立层级。普通空阵位仅使用12%竹叶色填充与36%青玉色的1px轮廓；仅候选、悬停和键盘焦点使用浅绢高亮，避免32个亮白圆盘压过战场。

## 字体与字级

| 角色 | 字体 | 设计字号 / 行高 |
| --- | --- | --- |
| 正文、提示、按钮 | 本地 `assets/chinese.otf`，回退微软雅黑 | 12–17px / 1.45 |
| 关卡标题 | 宋体 / 华文宋体，回退本地中文字体 | 27px / 1.25，字距2px |
| 武将姓名 | 同上，控制使用范围 | 22px / 1.15，字距2px |
| 主要资源、波次 | Consolas / 等宽系统字体 | 23px / 1.1 |
| 卡片价格 | 同上 | 16px / 1 |
| 关键状态、定位、提示 | 本地中文字体 | 12px / 1.35–1.45 |
| 武将战场名签 | 本地中文字体 | 姓名13px，阶数12px |
| 辅助标签、来源页脚 | 本地中文字体 | 9–10px / 1.5 |

字体只从本地加载。小字只承担辅助信息；已上阵、可招募、军饷差额、战场阶段、定位与操作提示至少12px。将牌姓名下移至y24，为上沿12px状态签留出独立空间；主操作保持17px，避免所有文字同大同粗。

## 布局标注

所有数值为1280×720设计画板坐标。`main#artboard` 由共享预览脚本在父视口内等比缩放，不对地图或UI分别拉伸。

| 区域 | x / y / 宽 / 高 | 说明 |
| --- | --- | --- |
| 顶部军令条 | 0 / 0 / 1280 / 80 | 关卡、状态、波次、耐久、军饷、计时、速度、主操作 |
| 战场 | 16 / 88 / 1248 / 472 | 接近1844×698正式裁切比例，完整保留32阵位 |
| 上阵提示 | 145 / 562 / 最大737 / 最小22 | 收在将册标题行，避免遮挡底排阵位，明确当前下一步 |
| 底部浅绢 | 0 / 553 / 1280 / 167 | 只承载将册、成长和来源标记 |
| 将册标题 | 26 / 565 / 924 / 18 | 标题、操作提示、分页入口 |
| 五将横排 | 24 / 590 / 926 / 99 | 5等列，列间8px，头像67×90px |
| 成长检查器 | 970 / 561 / 286 / 137 | 姓名、定位、成长入口与条件说明 |
| 主操作按钮 | 顶部右端 / 161 / 49 | 与阵位选择保持独立，不因选将移动 |

卡片姓名、定位、价格的左边界统一；全部原始头像保持纵横比例。卡片不标注稀有度，也不添加手动大招或付费货币。

## 状态设计

| 优先级 | 状态 | 可见反馈与操作 |
| --- | --- | --- |
| P1 | 备战 | 顶部“布阵中”；军令按钮“开始守关”；初始关羽、黄忠已上阵，赵云选中，军饷240 |
| P1 | 查看与上阵 | 点击将牌只更新查看对象；点击地图空阵位才招募。将册提示与取消选择始终可达 |
| P1 | 已上阵 | 将牌右上角青玉实色签“已上阵”，允许查看成长，不重复招募 |
| P1 | 可招募与选中 | 可招募文字签；选中额外使用双线边界与上沿菱形记号 |
| P1 | 军饷不足 | 头像适度去色，文字签说明不足，价格使用铜色虚线；顶部军饷出现“紧缺” |
| P1 | 运行 / 暂停 | 主按钮分别为“暂停 / 继续”；暂停保留战场与已布阵信息，顶部状态采用铜线强调 |
| P1 | 未选将 | 共享脚本显示选择提示；不自动招募，不用空白检查器暗示错误 |
| P1 | 结算 | 由共享预览层展示守关结果；保持与正式战斗隔离 |
| P2 | 键盘与减少动态 | 按钮有3px可见焦点轮廓；响应系统减少动态设置 |

共享脚本 `preview.js` 管理32阵位、人物、军饷和演示状态；共享 `preview.css` 提供场景与弹层基础样式。此页只定义A方案视觉。预览不存玩家记录，也不调用正式战斗。

## 真正重绘的后续要求

| 优先级 | 对象 | 可验收要求 |
| --- | --- | --- |
| P1 | 地图结构 | 保留正式70路点与32阵位净空、入口、出口与关城功能位置；不能通过移动路线制造更好看的构图 |
| P1 | 地图形体 | 绘制连续起伏的草土、可辨识路肩与自然转折；田树形成小簇，关楼成为明确视觉焦点；禁止只给旧图套色或描色块后称为重绘 |
| P1 | 武将形体 | 衣甲区分布、皮、金属；统一脚底锚点、光向、描边粗细与镜头角度；保留关羽长髯、赵云红缨枪等身份轮廓 |
| P1 | 战场辨识 | 同比例展示地图与全身像，验证32阵位与射程范围可读；人物不能被青绿地图吞没 |
| P2 | 生产交付 | 地图、透明全身像、头像、材质部件分层输出；在Unity实际分辨率验证后再进入正式资源替换 |

## 取舍

该方向的优势是地图连续、操作位置稳定、青玉与原有田园地图容易协调，适合长时间横屏守关。代价是底部占用167px，五将信息必须克制；扩展到十名随军武将时需要真实分页，不能把十将挤成小图标。成长检查器压缩到右下角，复杂升级对比应使用专门弹层，避免继续挤占战场。

本文件与HTML属于可比较、可回退的设计提案，不改变既有v3/v4稿、正式Unity代码或游戏规则。
