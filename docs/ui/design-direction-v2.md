# UI 改稿：青绿微缩沙盘

## 原稿诊断与设计目标

原稿建立了基本配色，但人物、地形和界面仍显得像示意组件。人物的冠帽、甲片、须发与姿态需要形成独立轮廓；战场需要可信的接触阴影与地形侧厚；空阵位不应像白色打孔网格。精修应围绕这些基础质量展开。

青绿地形与暖沙道路成为视觉主体，深青外框让明亮沙盘集中在视野中。岩石、竹丛、台地边缘和小旗承担世界感，装饰安排在路线之外。统一受光、描边与材料明度，以仔细调整的层次建立精致感。

人物采用原创的微缩棋兵造型。全身棋子和卡片肖像来自同一套图形，绿袍长须与长刀、银盔白袍与长枪、深甲浓须与蛇矛分别形成识别线索。有限的像素要优先交给脸部、兵器与姿态，手工校正边缘和细节，而不是让角色只靠名字区分。

信息按操作重要性排列。顶部收紧章节、军饷、城防、波次与敌将情报；战场保留大面积连续空间；底部突出当前选中的武将与升级按钮。已出阵、可招募和选中状态使用不同明度、文字与边框共同表达，不能只靠颜色。

整体保留轻松的演武气氛。命中弧光、火攻和军旗只作为少量视觉焦点，避免覆盖路径。每一处阴影、字号和内边距都应服务可读性；后续真正进入 Android 时，再以手机画面确认密度与触控，而不将静态稿当成适配验证。

## 视觉系统

| 用途 | 主色 |
|------|------|
| 深青框架与主文字 | #193E37 |
| 己方与选中 | #47795D |
| 地形基调 | #94AB7E |
| 暖沙道路 | #DEC79F |
| 纸质面板与文字 | #F1EAD9 |
| 敌军与威胁 | #B65B49 |

- 标题使用本机楷体，正文使用微软雅黑，数字使用 Segoe UI；仅将字形渲染在概念图中，不复制系统字体文件。
- 采用 1920×1080 横屏概念画布。画面方向仍为当前方案建议。
- 顶部以紧凑信息组呈现资源与战况，当前敌将比下一敌将有更强的视觉权重。
- 底部保留六名角色一屏的显示方式，本局共十名，更多按钮进入余下人物。
- 地图保留 34 个阵位，其中 4 个已部署、30 个空位；空位为低对比椭圆基座。
- 本关中场张辽与最终吕布均不出现在己方十人名单。
- 当前选中关羽，升级价格、血量和伤害提升仅是视觉示例。
- 审图后将地表提亮、敌将改为朱砂底座和红底姓名牌；卡片头像与姓名保留独立安全间距。

## 操作状态规范

| 状态 | 建议表现 |
|------|----------|
| 普通空阵位 | 低对比基座；不常驻编号或大加号 |
| 选中武将 | 单一选中边框、清楚的射程和升级面板 |
| 已出阵 | 显示“已出阵”标记；保持人物仍可辨认 |
| 可招募 | 军饷价格清楚，卡片可点击 |
| 军饷不足 | 保留价格，显示差额，不用强烈报错弹窗打断战斗 |
| 已满级 | 操作区明确显示“已满级”，不继续显示升级价格 |
| Boss 禁选 | 战前选将时显示“本关敌将”，并保留人物资料可读 |

上述是后续交互实现的视觉规范；当前静态稿只展示部分正常状态。
