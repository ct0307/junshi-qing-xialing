# 武将特色成长、进军节奏、竞速记录与UI改版草案

日期：2026-11-06。状态：用户回复“好”批准整体方案，进入实施；实际完成情况见hero-growth-implementation-plan.md与验证记录。

## 1. 目标与已确认要求

让玩家持续看到守将出手、升阶后的能力变化和成群击退反馈，同时用进军倍率提供主动挑战与更快通关的空间。

用户提出：每名武将应有自己的特色升级，不能只增加伤害；基础攻击不能太慢；每关增加最快通关时间；UI需要明显优化。

用户已明确选择：进军倍率同时加快小怪与Boss移动、出兵和波间等待；武将攻击频率不随倍率改变。

保留25人、战前最多10人、同关全部Boss禁选、每将每局一次招募、三级成长、大量阵位以及城防归零才失败。沿用认可的v3青绿沙盘方向，历史v3/v4源稿不变。

## 2. 方案比较与推荐

| 方案 | 内容 | 取舍 |
| --- | --- | --- |
| 参数精修 | 保留现有单一出手，仅让升级改变射程、目标数等参数 | 改动较小，但张飞、吕布等仍有长时间不出手的问题 |
| 快普攻＋独立特色技能（推荐） | 持续普攻提供节奏，特色技能独立自动触发，二三阶改变机制 | 能同时解决等待感与成长辨识度，需要重新校准输出、经济与五关参考 |
| 分支天赋 | 每次升级选择不同路线 | 选择更多，但显著增加学习和操作负担，首轮不采用 |

本次推荐第二种；二阶获得一项明确的特色变化，三阶继承并进一步改变覆盖、转火或协同。基础数值允许小幅成长，但不再以统一伤害倍率作为全部升级收益。

## 3. 出手节奏与技能边界

当前大部分等级只改变1／1.45／1.90倍基础伤害；曹操与鲁肃另有少量等级参数。吕布连续重斩名义周期约5.86秒，张飞与司马懿至少4秒；荀彧、吕蒙主要依赖事件触发。它们具备差异，但缺少持续出手的反馈。

首轮试调目标：常规普攻约0.6～1.0秒一次，重型和辅助约0.9～1.2秒一次；特色技能通常3～6秒或按明确事件触发。具体值作为实现阶段的配置与实测对象，不视为已经验证的平衡结论。

- 普攻和特色技能有独立就绪时间，蓄力不让武将长期停手；技能动作播放可短暂覆盖普攻动作，但不能吞掉规则攻击或重复结算伤害。
- 张飞不能每次快普攻都眩晕，吕布不能每次都重斩；吕蒙伏击、荀彧协射仍受各自事件与冷却限制。
- 快普攻的单次伤害、原有技能倍率与升级伤害一起重算，避免把快普攻直接叠在旧版全部输出之上。
- 升级、调位和切进军倍率不重置攻击／技能就绪时间，不赠送免费连发；升级界面与规则读取同一份成长数据。
- 普攻、技能命中及额外追击保留真实目标身份，展示能够区分普通出手与特色发动。

三阶继承二阶。下表确定机制方向；次数属于首轮上限设计，射程、费用与伤害在实现计划中按整套输出预算配置。

| 张角 | 雷链由至多4名增加为5名不同目标 | 雷链可分叉，共享去重集合，整次至多命中7名不同敌人 |
| 吕蒙 | 伏击后留下追踪标记，离开伏击区再背袭，每敌最多两次 | 背袭波及附近至多两敌，波及不再触发伏击或背袭 |
| 曹操 | 号令额外覆盖圈外最近一名友军 | 号令让至多三名受益友军各追加一次普攻，追加不触发协同或自身追加 |
| 貂蝉 | 同时使两名高威胁敌人易伤，同类易伤不叠加 | 易伤目标被击退后向附近至多两敌传递剩余效果，每次技能只传播一轮 |
| 庞统 | 连环由两名扩为三名，传伤只扩散一层 | 节点倒下后补入一名新敌，整组仅补一次，不刷新到期时间 |
| 荀彧 | 原目标已被友军击退时，协射改射附近存活敌人 | 协射变成两支分箭，共用一次冷却，不递归触发 |
| 司马懿 | 干扰标记使该敌本次施技后的破绽期延长0.75秒，仅一次 | 标记者施技后向另一名预警中特殊敌军追加一次干扰，不继续传递 |
| 孙尚香 | 技能击退后追射第二名残血敌人，不重置技能冷却 | 追射可跨路线至第三名残血敌人，整轮目标数封顶 |
| 张辽 | 后向溅射延伸到第二排，次目标至多3名 | 首目标倒下后追加后向冲击，只命中本轮未受溅射者，至多2名 |
| 姜维 | 当前姿态无合适目标时，按距离提前换枪阵／弓阵 | 换阵后的首轮枪弓接力，整轮仅接力一次 |
| 华佗 | 首次普通漏兵后可提前医护，与波末共享每波及整局额度 | 提前医护也响应Boss突破，仅城防仍存时生效，不挽救已归零城防 |
| 鲁肃 | 首兵出场预支一半当波补给，波末只发剩余 | 成功招募或升级可预支本波未结补给补差额；不足则无副作用拒绝 |

防止循环与收益失控：Boss硬控继续最多0.3秒并保留免疫；司马懿保留目标3秒干扰免疫，同次Boss预警累计追加至多1.4秒、普通军医同次技能累计追加至多1.5秒；华佗每波最多2、全局最多8，不超满城防；鲁肃全局最多100，预支和波末共用账本。传伤不再传伤、协射不再协射、追加攻击不再生成自身；陆逊、箭雨、链电和多段技能分别使用整次技能预算，一阶陆逊的死亡传播也须限制在1代、4名不同敌人以内。

## 5. 进军倍率与两个战斗时钟

建议首版提供1×／2×／3×，界面名称为“进军”，允许战斗中切换。更高倍率会减少敌军在射程内可受攻击的时间，因此是主动增加压力，并不保证所有阵容在所有倍率都能通关。

| 内容 | 推荐推进依据 | 确认状态 |
| --- | --- | --- |
| 小怪与Boss移动、出兵、波间等待 | 进军时间＝有效运行实秒×当前倍率 | 用户已确认 |
| 武将普攻、特色技能冷却 | 有效运行实秒，不乘进军倍率 | 攻频不随倍率为用户要求；技能冷却口径为推荐 |
| 蓄力、灼烧、印记、控制、免疫、Boss技能与预警 | 有效运行实秒，保持可读、可反应的时间 | 推荐 |
| 计时军饷 | 进军时间，保留相同推进进度下的补给预算 | 推荐，待整体审阅 |
| 攻击动画、受击、退场、反馈限频 | 有效运行实秒，暂停冻结 | 推荐 |
| 通关计时 | 实际前台运行时长，排除备战、暂停和后台；不乘倍率 | 推荐 |

军饷随进军时间的原因：3×已经减少可用攻击次数，若再减少三分之二计时收入，会叠加经济压力。收入按每步进军增量累计，切换倍率只影响后续，不允许用“总时间×当前倍率”追溯发钱。当前每实秒收入应在情报／详情中准确显示。

示例：1×运行2秒，再3×运行3秒，实际用时5秒、进军11秒。若基础每进军秒收入2，则累计22军饷。暂停期间两个战斗时钟、收入和技能全部冻结，恢复不补算后台时长。

波间倒计时显示当前倍率下的预计实秒；切换倍率立即换算剩余排程，不能重启当前波、重复出兵或重发波末收益。使用固定实秒规则步进，不能继续把整个规则累积时间乘Speed。

## 6. 每关最快记录

- 点击“开始守关”开始，包含首波等待和波间等待；首次胜败立即冻结。备战、暂停、后台不计入。
- 计时独立于进军倍率，按实际前台运行时间累计；固定步欠账或低帧率不得产生虚假的更短成绩。
- 仅合法胜利写最快。沿用城防仍存即可胜利的现有条件，Boss突破后获胜也计入；附带显示城防、漏兵及Boss突破，最快不等于完美守关。
- 每关一个最快记录，不按倍率拆榜；保存有效毫秒数、使用过的倍率摘要，以及该纪录对应的城防与漏兵快照。只记录实际运行过的倍率，暂停中空切不算使用。
- 严格更快才更新；相同或更慢保留原纪录。准备、失败、旧会话、重复结算不写最快。零、负数、非有限、溢出或损坏值不作为有效纪录。
- 新键包含规则版本，旧通关与最佳城防键保持。旧城防记录不推算时间；未建立本版有效时间时显示“最快 —”。无效时间不能阻碍保存合法通关与城防。
- 关卡卡片展示“最快03:42”；胜利页展示本次／个人最佳。没有旧时间时显示“首次纪录”，打破已有纪录时才显示“快了12秒”。结算应保留比较前的旧纪录，避免先保存再比较导致永远不出现新纪录。
- 使用既有本地存储，不引入联网排行榜或账号系统。

## 7. UI改版

| 布局 | 优点 | 代价 |
| --- | --- | --- |
| 上下军令台（推荐） | 保留大沙盘，上部双行HUD，下部五卡两页＋固定升阶预览；十将正好两页 | 升阶预览需控制重点，详细说明另开详情 |
| 侧置常驻详情 | 成长、技能和记录阅读空间更足 | 缩窄地图，小屏棋兵与密集敌军更难辨 |

推荐布局：

```text
关卡　军饷　城防30/30　用时02:18　暂停
第4/8波　余敌12　Boss生命／预警　进军2×
────────────────────────────
              青绿沙盘
      道路、阵位、棋兵、覆盖和击破反馈
────────────────────────────
军令：敌将突破，城防−15，继续守关
──────────────────┬─────────
五张武将卡，翻页1/2  │ 赵云　一阶→二阶
头像／名字／费用／状态│ 贯穿枪线加宽
                    │ 升阶费用／不足差额
```

- 选将卡主体只查看详情，独立勾选区域加入／移出；推荐阵容一键可用，不依赖长按。
- 升阶预览首先显示可核对的当前→下一阶变化，例如“协射目标：1→2”或“追加追击：无→有（至多1次）”；范围变化同时对比前后覆盖，不能只写“增强／加宽”。其次才是基础数值，费用、不足差额、满阶状态固定位置；全部来自实际成长配置，不写展示假值。
- 计时与进军倍率相邻但清楚区分；首次提示“敌军移动与出兵加快，守将攻速不变”。
- 城防重损失用短促的−15与数值变化强调，低城防采用明确颜色与文字；重要Boss提示优先于普通通知。
- 密集敌军改善展示层错位、血条与层次，真实路线／命中坐标仍准确，不用假命中制造爽感。
- 1280×720作为小屏截图基准，关键正文目标至少16像素，主要点击目标约48像素起；实际手机按逻辑触区、像素密度和安全区验收，截图不替代手指实测。
- 1920×1080与2400×1080复核，不以缩小所有字体塞入更多内容；复用现有字体、人物与uGUI资源，不增加外部框架。

## 8. 实现边界与顺序

1. 先建立成长数据与双时钟契约，明确普通命中、技能命中、追加命中的触发边界。
2. 用关羽、吕布、赵云、张飞、华佗、鲁肃覆盖持续输出、蓄力、贯穿、硬控、恢复与经济，再完成其余19人；最终交付覆盖25人，不缩减范围。
3. 加入最快记录、存档兼容与新纪录结算；实现新HUD、卡片、升阶预览和选将操作。
4. 重新校准五关正常倍率与主动加压倍率，复核多套合法阵容、输出、经济和Boss容错；最后重建两平台产物。

后续预期文件范围：Domain中的Definitions／RuntimeTypes／BattleSession／CombatSystem与成长解析；内容生成器、database和清单；GameProgress／GameFlow／MenuViews／BattleView／BattleResultView及相关反馈；规则与Unity验收脚本、运行时契约和说明。具体拆分进入实现计划后确定，避免为25名角色分别建立重复框架。

## 10. 本次证据边界

本节记录方案编制时的证据：当时只研究现有代码、配置和截图，未实现新机制，上一版81项规则及构建只证明上一版行为。用户批准后已进入实施，当前验证见hero-growth-runtime-acceptance.md及实施计划；不以本设计稿作为功能已通过的证据。

整体审阅需特别确认：快普攻＋独立特色技能、25人成长方向、军饷随进军推进、技能与控制按实秒、所有合法胜利计入最快，以及上下军令台布局。
