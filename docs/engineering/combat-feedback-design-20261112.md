# 战斗体验第一轮：击破反馈与配合可读性

日期：2026-11-12。状态：**首轮表现版已实现并交付独立Windows**，见[验收记录](combat-experience-acceptance-20261112.md)。评审收敛为分两步落地、0.4/0.7秒对照、固定音高扩展后置；以[实施计划](combat-experience-plan-20261112.md)为本轮执行范围。以下保留设计依据，最终事实以验收记录为准。

依据：[战斗体验路线图](combat-experience-roadmap-20261112.md)、项目[AGENTS.md](../../AGENTS.md)和[Jade试玩记录](../../UnityGame/Builds/JadeApp-20261112/acceptance.json)。设计阶段已核对源码并复验基线，后续实施验收单独记录，不引用旧版通过数量作为新版证据。

## 目标与方案选择

目标是让连续击破有轻重、让玩家看懂已有配合为什么有效。保持青绿行军界面、伤害公式、经济、敌军、波次、技能冷却和进军倍率语义。先交付一个独立Windows表现版供对比，再根据试玩决定数值实验。

| 方案 | 内容 | 取舍 |
| --- | --- | --- |
| A：表现先行，推荐 | 连破采用0.7实秒固定窗口和3／6／10档；补真实区域、状态、传伤与协射来源 | 保持玩法结果可比较，先判断反馈和配合理解是否改善 |
| B：仅补配合标记 | 保留现有0.4秒连破，只补三组可读性 | 范围更小，但连续击破的反馈变化有限 |
| C：同时改表现与数值 | 叠加普通兵降血、批次加密和反馈 | 难区分收益来源，可能影响计时军饷与最快纪录，放到后续独立实验 |

本设计采用A。0.7秒已在新Windows表现版生效，是固定窗口试验参数，不会无限续时。旧Jade保留0.4秒；是否更解压由用户对比试玩判断。

## P1：三档连破

### 计数与时钟

- 只消费真实 `kill` 事件，`TargetEnemyId > 0` 且本局从未计入才有效。命中、漏兵、重复ID及合成反馈不计数。
- 在首个有效击退的发生时间 `t0` 开启固定窗口 `[t0, t0+0.7)`；后续击退不延长窗口，到边界的击退开启下一窗口。不同窗口不累加。
- 为所有 `BattleEvent` 增加 `OccurredAt`，由 `BattleSession.Emit` 写入 `Session.Time`。同一帧取出多个固定步事件时，仍按真实发生时间和原事件顺序分组。
- 大帧取出旧事件时，短反馈按发生时间扣减已过去的寿命；已经过期的连线、标记或连破文字不重新活满一个周期。计数仍依照全部真实事件完成，过期短音丢弃。
- 1／2／3倍只改变进军；窗口、飘字、标记与动作持续时间按有效实秒。暂停冻结，终局和重开清空。
- 计数逻辑与特效对象是否分配成功分离；达到90对象预算时允许省略普通效果，不能改变计数或让声音依赖图形对象创建。
- 不产生奖励、断连惩罚、武将组合击破归因或新存档内容。

### 显示与声音

| 真实次数 | 显示 | 首轮表现参数，1920设计坐标 |
| --- | --- | --- |
| 1～2 | 保留已有击退与赏金反馈 | 原局部48范围退场环；不额外显示连破 |
| 3～5 | 连破 ×实际次数 | 青玉边／暖金字，字号29，入场缩放峰值1.06 |
| 6～9 | 连破 ×实际次数 | 暖金字，字号33，入场缩放峰值1.10；一次72范围局部冲击 |
| ≥10 | 连破 ×实际次数 | 暖金亮边，字号37，入场缩放峰值1.14；一次96范围局部冲击 |

每档只在首次跨入时触发冲击，文字更新始终保留实际次数；同一窗口复用一个标签，不让10次击退产生10个连破飘字。标签跟随该窗口击退位置均值，并限制在沙盘可见区域内；存活0.8实秒，只有有效次数更新才重置文字寿命。新窗口首次达到3次时，复用或替换上个窗口尚未退场的标签，不继承旧档位。

声音复用现有 `enemy.defeat` 片段，3／6／10档分别采用相对增益0.80／0.95／1.00。同一事件批次只播放跨入的最高档，并替代该批次的普通击退短音。跨批次任意0.2实秒最多一次分档短音；片段原冷却较长时继续遵守原冷却。过频时丢弃，不在稍后补播。同档不重复触发。继续受普通声部、每秒16次普通音和现有总声部预算限制，Boss预警仍走关键声部及现有压低机制。

三档固定音高1.08／1.00／0.94为原设计候选，经实施前评审后置；本轮不修改 `AudioVoicePool`，保留原普通音0.97～1.03随机变体及既有声部寿命计算。

不增加全屏闪光、持续震屏或强制慢放。已有命中闪亮和约0.24秒退场保留，避免同时改变太多反馈变量。

## P1：三组配合的真实表现

### 诸葛亮＋周瑜：看见留人和火区

- 诸葛亮一阶保持真实命中后的减速提示；二阶显示一个风眼，三阶显示实际创建的两个风眼，寿命2.5实秒、半径105。没有创建风眼时不画。
- 周瑜一阶显示半径95的火区；二、三阶沿实际路线绘制 `Travelled−75～+115` 的火带，寿命2.5实秒。不能把武将 `SkillRange` 当作火区半径，也不能用圆形覆盖伪装道路火带。
- 范围图形放在人物下方，风眼用低透明青玉边，火区用低透明暖橙边。新风眼替换旧风眼时同步移除旧边界；重叠火区遵循真实存续情况，图形淡化不改变同源取最强的规则。
- 敌人是否减速、处于火区／灼烧／余烬，读取当下规则状态；离区、到期、死亡或对象池复用后更新／清除。每个敌人最多同时显示两个短状态，优先级为眩晕、减速、连环、燃烧；区域边界和连线补充未显示的状态。
- 此组合只有已有站位与覆盖收益，不增加专属伤害倍率或组合播报。

### 庞统＋关羽：连线对应真实传伤

- 连环建立时，短暂显示完整真实成员之间的细线，0.35实秒后退去；成员保留“链”标记直到原3秒到期。二、三阶第三成员必须包含在快照中。
- 真实传伤发生时，只沿初始受击敌人到真实接收敌人的方向亮线0.18实秒。只表现已经结算的传伤，不根据站位或文字notice推断。
- 三阶补入只连接实际新增成员，沿用原到期时间，不重开3秒；敌人死亡后线端不追踪池中复用的另一敌人。
- 关羽仍只显示自己的单点／追斩目标，连环扩散由庞统机制表达。
- 现有“连环传伤”notice发生于施加连环，`Amount=.3` 是倍率，不能拿来画一次真实命中。
- 保留现有计算口径：原目标减伤／易伤后计算值乘0.3，再由接收者计算其减伤／易伤；该值未按原目标剩余生命封顶。本轮不改公式，不标成“实际扣血的30%”。

### 荀彧＋主力：补箭来源明确

- 用现有真实 `attack` 的荀彧起点和敌人目标绘制青玉箭迹，与纸白普攻区分；同一次出手只画一支对应真实箭的弹道。
- 补充触发友军身份后，在该友军与荀彧之间闪现0.18实秒细线；荀彧处短显“协射”0.45实秒，同来源文字0.8实秒内最多一次。
- 二阶原敌死亡后的改射、三阶第二箭，全部直接使用真实事件目标；首箭可能射向荀彧自身射界外的原敌，不做UI侧射界裁剪。
- 独立1.5秒冷却及不递归保持；普攻不误标成协射，不新增第二次伤害、第二次攻击声或虚假的补刀提示。

## 数据与组件边界

沿用现有事件流，新增信息只用于展示和验收，不参与目标选择、随机数、伤害、技能计时或经济。

| 数据 | 拟议契约 | 消费方 |
| --- | --- | --- |
| 事件发生时间 | `BattleEvent.OccurredAt` 为发出时的有效实秒；所有事件同源填写 | 连破固定窗口、跨大帧一致性检查 |
| 协射触发者 | 协射 `attack` 增加 `TriggerHeroId`；`HeroId` 仍是荀彧，目标字段语义不变 | 来源短线和协射箭；不靠中文Text识别 |
| 真实传伤 | 新 `link_hit`；`HeroId` 为庞统，`TriggerHeroId` 为原攻击者，`SourceEnemyId` 为起始敌人，`TargetEnemyId` 为接收者，起终点为结算时坐标，`Amount` 为接收者结算后的伤害计算值 | 传伤线；原 `hit` 继续承担伤害数字与命中闪亮，避免重复飘数 |
| 连环生命周期 | 新 `link_created`／`link_replaced`，携稳定组ID、原到期时间、建立／补入时有可信位置的完整存活成员ID与坐标副本，以及被替换／新增成员ID；嵌套结算前已移除的成员不输出默认坐标，不改变玩法组集合；不消费或重排旧事件 | 完整建立线和补入线，不从取事件时的存活成员倒推历史 |
| 区域快照 | 只读副本包含会话内唯一区域ID、来源武将、形状、中心／半径或路线ID／距离区间、到期时间 | 风眼／火区边界；路线火带直接采样既有路径 |
| 连环快照 | 稳定组ID、庞统身份、完整存活成员ID、原到期时间；补入更新成员不刷新时间 | 链标记及当前持续状态校验；不还原建立／补入历史 |
| 敌军状态快照 | 真实实例ID、减速／眩晕／燃烧状态及有效截止时间；燃烧含当前火区和余烬 | 简短状态标记，按实例回收 |

区域、连环和持续状态以规则只读快照为准，过期／覆盖替换时不依赖一次事件自行续命；不得向UI泄露可写的内部 `FireArea`、`SlowArea`、`LinkGroup` 或敌人实例引用。只读查询不得消费事件或改变规则状态。短线的创建由真实建立、补入、传伤和协射驱动；同批内已死亡成员使用事件中的实例ID／位置副本，不绑定其他复用单位。生命周期事件只表现尚余寿命的短反馈，当前状态仍以快照为准。颜色或细节可降级，真假不能降级。

连破聚合放在独立的展示状态组件中，由 `BattleView` 每批事件只处理一次，并把计数／档位结果同时交给 `BattleEffects` 和 `GameAudio`。保留现有所有攻击、命中、击退和终局事件的顺序，音频采用整批最高档合并；不在图形和声音里各做一套不一致的计数。

`kill.HeroId` 继续保持原语义，不为本轮新增攻击者或组合击破统计。`link_hit` 只画语义短线，不作为新的命中、伤害或连环触发入口；协射追加字段也不再触发攻击逻辑。

| P1 | 声音 | 同批只最高档、同档去重、0.2秒限频、静音／暂停／终局无延迟补播；普通随机音高范围；普通每秒16次及总声部预算、Boss优先不倒退 |
| P2 | 人工体验 | 用户对比清兵连贯性、配合是否看得懂、噪声是否过强、布阵是否仍有作用；无真机时保留触控／帧率／发热待验证 |

现有 `UiBattleFeedbackChecks` 在多个用例写死0.41／0.51秒，修改窗口时必须改成明确的新边界断言并保留“不续时”的反例，不能只放宽断言。现有音频测试缺连破档位，现有终局检查也不足以覆盖新连线／区域，均须补齐。
