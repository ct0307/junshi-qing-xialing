# 军师请下令：布阵竞速核心玩法改进方案

日期：2026-11-19。状态：本方案已获用户授权并完成P1、P2实施，独立包Race-20261119及自动验收已交付，真人与真机待验；战斗规则仍为faction-army-v1，竞速资格all-boss-v1。实际结果见[实施验收](race-implementation-acceptance-20261119.md)、[Word计划](race-implementation-plan-20261119.docx)与[逐关策略参考](race-strategy-reference-20261119.md)。以下规则、诊断与“尚未实施”等表述保留设计冻结时上下文，现状以实施验收为准。

## 1. 核心定位与选定方案

核心定位：布阵竞速塔防。玩家通过阵容、阵位、招募和升阶顺序，承受更高进军压力，在1×／2×／3×之间动态切换，反复刷新同关个人最快通关时间。清兵与成长反馈支撑单局满足感，竞速支撑重玩。

已比较三种方向：任意守关胜利都计主竞速，容错高但可能奖励放走难杀Boss；全Boss击退才计主竞速，可以让提速始终接受Boss战检验；按固定倍率拆榜，会增加入口和规则，限制动态切换的作用。

选定“普通通关保留容错＋全Boss击退主竞速＋动态倍率同榜”。普通漏兵可以用城防承担，Boss突破后仍可完成普通通关，但该局不写入新主竞速最快。提高倍率是缩短时间的手段，真正目标是更短的合格通关用时。

## 2. 普通通关与主竞速资格

| 项目 | 普通通关 | 新主竞速有效成绩 |
| --- | --- | --- |
| 胜利条件 | 全部波次完成、城防仍存，沿用现有规则 | 先满足普通胜利，再满足本关全部Boss真实击退 |
| 普通漏兵 | 允许，城防不归零即可 | 允许，不要求满城防或零漏兵 |
| Boss突破 | 仍扣15城防并离场，城防仍存可继续获胜 | 任意一次Boss突破均不合格 |
| 使用倍率 | 1×／2×／3×，允许动态切换 | 同样允许动态切换，不要求全程某个倍率 |
| 保存与反馈 | 保留通关、城防、本次用时及最近通关等普通结果 | 仅合格成绩参与主竞速最快比较 |

UI名称统一为“竞速最快”，资格说明为“守关成功，且全部敌将击退；普通漏兵允许”。通关但Boss突破时明确显示“守关成功；本局有敌将突破，未满足竞速资格”，保留这局的通关结果与用时，仍可调整再试。

全Boss按出兵实例对账：由Waves.Groups中IsBoss敌军及Count建立预期出场数，规则层分别累计实际生成、真实击退和突破。合格必须满足预期全部生成、生成Boss全部真实击退、Boss突破为0。相同身份多次出场按不同实例计数。

不能用BossHeroIds数量代替出兵数：该列表用于己方禁选，可能包含额外声明。也不能根据满城防、总击退数、最后一次突破、已消费的事件文本或画面表现认定全Boss击退。当前Domain尚无完整Boss击退快照，此项是后续实施内容。

## 3. 倍率、时间与成绩比较

- 保留1×／2×／3×及当前双时钟原则：敌军移动、出兵、波间等待、计时军饷按进军时间推进；我方攻击、技能冷却及既有状态按有效运行实秒推进。
- 每关同一战斗规则版本、同一竞速资格版本使用一个本机主竞速最快，不按倍率另拆榜。全程1×、全程2×、全程3×与混合策略均可参加，按有效通关时间比较。
- 按实际有效运行实秒计时，包含首波和波间等待；备战、准备期调位、暂停、说明阅读和后台不计时。暂停不会推进冷却或收入，恢复不补算。
- 只有真实运行的倍率才计入摘要，暂停中空切不算。触碰3×不获得额外评价、积分或奖励，不能据使用过的最高倍率推断更快。
- 严格更快才刷新；同一保存时间不覆盖旧最快。城防、漏兵和倍率摘要用于解释打法，不设置隐含加分或同分城防排序。
- 首版不增加4×以上倍率、无限提速、额外倍率奖励或全局同步快进；先验证现有三档的策略空间。

当前ElapsedSeconds在输入帧开始累计整段时长，终局帧可能整体计入；保存毫秒不等于终点具有毫秒精度。正式竞速实施必须核对终局计时与固定步推进，增加跨帧率一致性验收，先冻结计时契约再建立新主竞速基线。

## 4. 玩家成长循环

入门先用1×掌握部署、覆盖与升阶，取得普通通关，再完成一次全Boss击退建立竞速纪录；之后尝试更早切2×、减少高压阶段降速，逐步挑战3×并刷新个人最佳。

倍率不设强制解锁，不要求先用固定2×获胜才能点3×。首次高倍率说明沿用已认可文案与暂停阅读、已读保存、系统中断保护；该项由原P2提升为P1，因为它直接解释核心玩法。

低压段提速、关键段回常速是允许研究的一种策略，不能预先宣称必然最优。每关需实际对照固定倍率和动态倍率；全程3×不是普通通关或主竞速发布的强制门槛。

## 5. 玩法改进如何服务竞速

| 优先级 | 方向 | 选定范围 |
| --- | --- | --- |
| P1 | 竞速资格、双时钟与新纪录契约 | 全Boss真实对账、有效实秒、跨帧率核对、新旧成绩分离，作为后续平衡基线 |
| P1 | 倍率说明与进步反馈 | 首次清楚解释压力；结算突出本次、此前最佳、快慢差值与首次／刷新／相同／未刷新；不合格时先说明原因 |
| P1 | 招募、军势与升阶取舍 | 对照第四名同营、核心二阶、功能补位三条路线，观察它们是否支持更早提速、减少降速和更快全Boss击退 |
| P1 | 关卡与出兵差异 | 用现有路线、兵种组合、错峰和Boss配兵形成不同的提速窗口；任何数值实验先单独对照，不同时改整套经济 |
| P1 | 战斗UI与手机可用性 | 沿用已认可顶栏、军令台、升级区精修，确保倍率、用时、城防及升级收益清楚，保留预警和真实施放反馈 |
| P2 | 复盘与低成本再试 | 沿用上一局名单调整，保存可信的首次失守事实；新局部署重新正常付费，不开放无成本撤退重招 |
| P2 | 倍率及策略摘要 | 新采集各倍率有效时长、有效切换时刻，以及实际阵容、部署和升级节点的轻量摘要，帮助比较打法 |
| P3 | 附加挑战与扩展 | 少将、指定阵容、零漏兵等作为后续可选目标；人物羁绊、更多武将、长期养成与更高倍率后置 |

五关重点分别为：黄巾利用回转道路重复覆盖；虎牢分配双路资源；官渡安排长短路投入先后与军医处理；赤壁平衡护卫清理、治疗与Boss输出；终局统筹三路的高压窗口。它们都应影响“何时敢提速、这笔军饷先花在哪里”。

现有三阶机制、跨阵营配合与军势收益继续保留。优先测试现有策略能否成立，再决定局部数值调整；普通兵统一降血、额外奖励和继续加攻不作为本轮默认改动。改变伤害、经济、排程或计时契约时重新冻结版本，不能沿用旧竞速比较结果。

## 6. 纪录与存档兼容

新主竞速按“关卡ID＋战斗规则版本＋竞速资格版本”定位。竞速资格版本预定为all-boss-v1；战斗规则仍沿用实际冻结版本，仅增加资格不冒称战斗数值已变化。

保留当前faction-army-v1及更早版本的最快、最近通关数据，不删除、不覆盖、不自动迁移成新竞速资格。旧快照虽有Boss突破数，但缺少完整出场及击退证据，不能因旧值为0就自动认证。

现有通关与最佳城防使用共享键yanyi.clear.<level>、yanyi.best.<level>，继续保留。新增竞速读写使用独立明确入口，不能仅替换GameProgress.FastestRuleVersion常量，造成旧接口默认读写含义改变。

普通通关和最近通关继续保存真实结果，竞速最快只接受合格会话；旧普通最快作为历史参考，界面清楚区分。未来如改变平衡，普通记录也按其实际战斗规则版本处理，不能继续用旧平衡版本写新结果。

无新竞速纪录时显示“竞速最快 —”和资格提示，首个合格成绩显示“首次竞速纪录”。比较时先捕获此前最快，再保存本次；不得先覆盖再计算差值。失败、Boss突破胜利、无效时间、重复结算或旧会话回调均不刷新新主纪录。

当前SpeedMask只能说明用过哪些倍率，不能推导持续时长、顺序、次数或切换时刻。后续摘要必须新采集，不给旧成绩补造轨迹。首版只做本机个人纪录与轻量摘要，不扩为完整录像、联网排行榜或防作弊系统。

## 7. 实施顺序与验收

### 第一批：冻结竞速契约

核对并补齐Boss实例快照、计时一致性和新纪录隔离；旧包、原始输入清单、原规则及旧成绩保留。先完成规则层与持久化契约测试，再接展示。尚未满足契约时，不用旧的普通最快冒充新竞速纪录。

### 第二批：让玩家理解并尝试提速

落实已认可倍率说明、战斗三处UI精修、合格／不合格结算及纪录差值。首次说明和结果页使用同一资格口径。配合独立试玩包开展首玩及手机验收。

### 第三批：逐关寻找更快的合法策略

先以黄巾做两套合法阵容的1×全Boss参考，再对比第四人军势、早升核心、功能补位及动态倍率。逐步扩展五关；记录军饷账本、首次升阶、首次失守、倍率有效时长、Boss结果与最终实秒。只有确认某个具体问题后再进行单变量波次或数值实验。

### 第四批：用复盘支撑持续刷新

加入沿用名单调整、首次失守事实及轻量策略摘要，观察失败后能否提出并尝试具体改法。附加挑战与更高倍率在现有三档出现充分可重复玩法后再评估。

验收清单：

1. 保持25将、最多10人、本关全部Boss禁选、每将每局唯一招募、Boss突破扣15与城防归零失败；不增加无成本撤退重招。
2. 普通胜利和新竞速资格分别验证。覆盖漏普通兵合格、Boss突破胜利不合格、多Boss及同身份多次出场、未生成完Boss、重复事件和无效会话；每个真实Boss仅计一次击退。
3. 用同一预定操作脚本对照30／60／120帧及长帧输入；终局计时差目标不超过一个固定规则步，不能依低帧率获取虚假更快成绩。达不到时先处理计时边界，再冻结新竞速基线。
4. 覆盖1→2→3→1动态切换、首波及波间等待、暂停空切、说明阅读、后台和恢复；倍率只影响后续推进，不追溯发钱、不重置波次、不补算暂停收入。
5. 同关同版本的合格成绩统一比较，严格更快刷新；首个、同时间、较慢、失败、不合格胜利、损坏与部分写入分别检查。旧最快、最近、通关、城防数据和跨进程重读独立核验。
6. 每关至少建立两条有意义差异的1×合格参考，并找到至少一条使用2×或3×、比本关1×参考更快的动态合格策略。该目标尚未验证，不把现有固定倍率九败视为所有策略无解；如未找到，继续诊断并保留真实结果。
7. 固定2×／3×继续作为压力样本，允许失败；不以固定3×五关全胜作为一刀切条件。以实际用时衡量进步，不以最高倍率或切换次数代替。
8. 5～8名新玩家首玩观察：建议至少4/5能说明“提速增加来敌压力、我方攻速不变、全部Boss击退才能记主竞速”，并在失败后提出一项具体调整；记录是否主动尝试刷新纪录。建议通过线不等于市场验证。
9. UI覆盖正常、无纪录、不合格胜利、刷新、失败、暂停和三尺寸／安全区；设备检查满10将、Boss与密集敌群下的触控、性能、发热、听感及存档。离屏图、模拟及构建不能替代真机和人工认可。

## 8. 证据与当前限制

当前规则、普通最快与双时钟见UnityGame/Assets/Scripts/Domain/BattleSession.cs、CombatSystem.cs，以及Presentation/FastestRecord.cs、GameProgress.cs。现有普通最快明确接受Boss突破胜利，倍率摘要已有SpeedMask；新资格、完整Boss快照和时长轨迹均未实施。

当前常速推荐五关全Boss击退，以及固定2／3倍十局九败，见faction-army-acceptance-20261112.md与既有军势日志。这些只代表对应策略；本方案的新竞速验收尚未执行。
